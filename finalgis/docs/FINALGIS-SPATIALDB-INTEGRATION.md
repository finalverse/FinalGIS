# SpatialDB exchange

scripts/spatialdb_exchange.py first invokes the canonical native FWD validator, verifies one static metre scene with identity placement and no simulation binding, then calls the existing SpatialDB authored GLB ingester, LOD/CAS compiler and Rust publication-seal validator. Source FWD and its full geographic frame/provenance remain pinned by digest alongside the derivative. This uses the existing scene-graph/v2 contract, not a new protocol or storage database.

The refined Montréal derivative finalized through the actual publisher into an explicitly owned local PostGIS fixture: graph274a7a07-a380-59e2-b47f-dbeb428d59bc, version115dce64c74b8fd4dd3baf7e9be424ebabc404082cc3039ae958174ac51b112f,5cells/9assets/2generated palette textures. Repeat publication is identical. Authenticated service readback verified the graph/asset hashes, anonymous401, another principal404 and identical bytes after a service restart.

A live test found migration006 only admitted synthetic profiles while the existing Rust worker already supported authored data. Additive migration008 and the fixture publisher now admit matching authored/synthetic seals with null measurement accuracy. Seven real trigger checks preserve owner/hash/closure/accuracy boundaries. Geographic v3 evidence remains required for geographic certification. The v2 navigation anchor is explicitly advisory: no MTM grid-north→true-ENU conversion or live world alignment is claimed. Source FWD retains the exact frame. Dataset discovery/spatial query continues through ordinary QGIS/PostGIS and the existing SpatialDB API; a new general-purpose desktop discovery/query browser is not implemented.
