# SpatialDB exchange

scripts/spatialdb_exchange.py first invokes the canonical native FWD validator, verifies one static metre scene with identity placement and no simulation binding, then calls the existing SpatialDB authored GLB ingester, LOD/CAS compiler and Rust publication-seal validator. Source FWD and its full geographic frame/provenance remain pinned by digest alongside the derivative. This uses the existing scene-graph/v2 contract, not a new protocol or storage database.

The refined Montréal derivative finalized through the actual publisher into an explicitly owned local PostGIS fixture: graph274a7a07-a380-59e2-b47f-dbeb428d59bc, version115dce64c74b8fd4dd3baf7e9be424ebabc404082cc3039ae958174ac51b112f,5 cells/9 assets/2generated palette textures. Repeat publication is identical. Authenticated service readback verified the graph/asset hashes, anonymous401, another principal404 and identical bytes after a service restart.

A live test found migration006 only admitted synthetic profiles while the existing Rust worker already supported authored data. Additive migration008 and the fixture publisher now admit matching authored/synthetic seals with null measurement accuracy. Seven real trigger checks preserve owner/hash/closure/accuracy boundaries. Geographic v3 evidence remains required for geographic certification. The v2 navigation anchor is explicitly advisory: no MTM grid-north→true-ENU conversion or live world alignment is claimed. Source FWD retains the exact frame. Dataset discovery/spatial query continues through ordinary QGIS/PostGIS and the existing SpatialDB API; a new general-purpose desktop discovery/query browser is not implemented.


The final consumer handoff is also executed: scripts/readback_scene.py fetched a SHA-pinned root and all3finest GLB leaves from the authenticated local SpatialDB service, preserved each BIN chunk byte-for-byte, and bound the verified graph's scalar materials into newly hashed derived GLBs. Core validated the resulting FWDv3 (3assets,5046triangles); Storm then rendered those received/material-bound assets for180Metalframes. This is direct publication-readback rendering evidence, distinct from the earlier raw-export captures. The source projected frame is retained verbatim; the advisory Earth anchor is ignored.

The bridge admits only an unbound, static, local-metre root publication with≤64embedded leaf cells and64MiB summed assets. It refuses external subtrees, textured leaves, redirects, remote endpoints, unsafe token files and digest/size mismatches. It is a bounded presentation cache/adapter, not another SpatialDB or a world publisher. Source GLBs, graph SHA, derived material hashes and unchanged BIN hashes remain inspectable in spatial-render-readback/readback.json. Its four independent material/integrity/network-boundary unit checks pass alongside native Release/ASan suites.
