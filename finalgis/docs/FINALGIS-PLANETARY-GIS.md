# Frames and scale

The public native transform ABI consumes explicit CRS strings and finite double x/y/z in traditional GIS order. The executable tests EPSG:4326↔EPSG:2950 and refuses nonfinite/unknown CRS input. GDAL/PROJ handle supported geodesy; no homegrown CRS engine or renderer floats are authoritative. Worker PROJ search paths are fixed to its configured data installation, preventing older host-QGIS PROJ databases from contaminating a newer native worker. PROJ network access is disabled.

The Montréal output frame is a projected MTM8 offset: EPSG:2950 origin[300619.334946641,5040809.30754108,19.070165634155273], vertical CGVD2013 orthometric height. Axes east,grid_north,up are explicitly not true ENU; z is not WGS84 ellipsoidal height. glTF Y-up maps (x,y,z)→(x,−z,y) before FWD placement. The fictional frame is arbitrary local Cartesian with no Earth ellipsoid. FWD can declare planetary/geodetic/projected/object frames and linear units down to nanometres; this milestone renders only the supported local metre profile. Continental/admin/interior datasets, non-Earth geodesy, astronomical transforms and dynamic LOD are not newly populated or certified here. Administrative geography is not assumed to be a strict tree.
